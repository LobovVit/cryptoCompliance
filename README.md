# Контур — крипто-комплаенс ВЭД

Рабочий MVP для компаний Беларуси: PostgreSQL, изоляция организаций, авторизация и роли, досье ВЭД, ручные решения и реальный санкционный скрининг криптоадреса через Chainalysis.

## Локальный запуск

Используется Go из `/Users/vitaliy/Developer/SDK/Go/current` и PostgreSQL 17 в Docker.

```sh
cp .env.example .env
docker compose up -d --wait postgres
set -a; source .env; set +a
make run
```

Открыть http://127.0.0.1:8080 и войти данными `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Первый владелец создаётся только в пустой базе. Пароль должен содержать не менее 12 символов. `.env` не коммитится.

Проверки:

```sh
make check
make build
```

## Авторизация

- Пароли хешируются bcrypt с cost 12. Исходные пароли в БД не сохраняются.
- В браузер передаётся случайная opaque-сессия; в PostgreSQL хранится только SHA-256 токена. Срок жизни — 12 часов.
- Cookie `HttpOnly`, `SameSite=Strict`; для production задаётся `COOKIE_SECURE=true`.
- Изменяющие запросы требуют CSRF-токен и проходят same-origin проверку.
- `owner` управляет пользователями и может изменять досье; `compliance` изменяет досье и запускает скрининг; `viewer` имеет только чтение.
- Каждая бизнес-запись содержит `organization_id`; запросы фильтруются сервером по организации из подтверждённой сессии.

Владелец может создавать пользователей API-запросом `POST /api/users` с полями `email`, `name`, `password`, `role`. Список пользователей — `GET /api/users`. Перед production стоит добавить экран администрирования, принудительную смену начального пароля, MFA/OIDC, блокировку перебора и отзыв всех сессий пользователя.

## AML / санкционный скрининг

Первая реальная интеграция — Chainalysis Sanctions Screening API. Настройте `CHAINALYSIS_API_KEY`. Ключ используется только backend и не попадает во frontend или отчёт.

Для сделки с заполненным кошельком `POST /api/deals/{id}/screenings` вызывает провайдера. Сохраняются:

- провайдер, адрес и время;
- статус `clear`, `match` или `error`;
- количество прямых совпадений;
- SHA-256 исходного ответа;
- исходный JSON провайдера для аудита.

Отсутствующий ключ, timeout, HTTP-ошибка или некорректный JSON дают `503` и сохраняются как `error`. Такой результат не становится успешной проверкой. `clear` означает только отсутствие прямого санкционного совпадения в ответе этого API. Полный KYT-анализ экспозиции, категорий риска и происхождения средств требует коммерческого Chainalysis KYT, AMLBot, Crystal или другого согласованного провайдера.

Для контрактного теста без внешнего вызова можно задать `CHAINALYSIS_BASE_URL` на контролируемый тестовый endpoint. В production оставьте переменную пустой, чтобы использовать официальный URL.

## PostgreSQL и аудит

Схема автоматически применяется из [schema.sql](/Users/vitaliy/Developer/Personal/cryptoCompliance/schema.sql) при запуске. Создаются организации, пользователи, сессии, сделки, проверки, append-only журнал и запуски провайдера. Изменение проверки выполняется в serializable-транзакции с optimistic version; устаревший клиент получает `409`.

Для production миграции нужно вынести в версионированный deploy-шаг, использовать отдельную роль БД без DDL-прав во время работы, TLS к PostgreSQL, backup/PITR и проверку восстановления.

## API

| Метод | Маршрут | Роль |
|---|---|---|
| POST | `/api/auth/login` | без сессии |
| GET | `/api/auth/me` | любой пользователь |
| POST | `/api/auth/logout` | любой пользователь |
| GET/POST | `/api/users` | owner |
| GET | `/api/deals` | любой пользователь своей организации |
| POST | `/api/deals` | owner, compliance |
| PUT | `/api/deals/{id}/checks/{key}` | owner, compliance |
| POST | `/api/deals/{id}/screenings` | owner, compliance |
| GET | `/api/deals/{id}/report` | любой пользователь своей организации |

## Границы текущей версии

Сервис не проводит автоматический KYB/PEP-скрининг юридических лиц, не загружает документы, не поддерживает MFA/SSO и не заменяет заключение юриста или комплаенс-специалиста. Список активов — технический справочник, а не перечень разрешённых активов. Записи провайдера доступны в БД администратору; криптографически неизменяемый внешний audit log ещё не реализован.
